### 2.4 My `chunk_by_heading` code

```python
def chunk_by_heading(doc, max_words=250):
    sections, current = [], []
    for line in doc["text"].splitlines():
        if line.startswith("## ") and current:
            sections.append("\n".join(current).strip())
            current = []
        current.append(line)
    if current:
        sections.append("\n".join(current).strip())

    pieces = []
    for sec in filter(None, sections):
        words = sec.split()
        if len(words) <= max_words:
            pieces.append(sec)
        else:  # one section longer than max_words: cut it into max_words pieces
            pieces += [" ".join(words[i:i + max_words]) for i in range(0, len(words), max_words)]

    chunks, buf, buf_words = [], [], 0
    for piece in pieces:
        n = len(piece.split())
        if buf and buf_words + n > max_words:
            chunks.append(make_chunk(doc, len(chunks), "\n\n".join(buf)))
            buf, buf_words = [], 0
        buf.append(piece)
        buf_words += n
    if buf:
        chunks.append(make_chunk(doc, len(chunks), "\n\n".join(buf)))
    return chunks
```

- **`heading:250` compared with my best fixed setting** (better / worse / same, and one reason): Same hit@3 as `fixed:200:0` (bm25 0.89, dense 1.00), better dense MRR (0.95 vs 0.89 at k = 3; at k = 1 0.89 vs 0.79), and slightly more context words (457 vs 406). Reason: chunks stop at section boundaries, so one fact is not split across two chunks and each chunk is about one topic.
- **Would the difference survive on a bigger corpus?** Probably yes, or grow, if the documents have consistent headings, because longer documents make fixed windows cut through sections more often. But this corpus is tiny (20 documents, about 22-26 chunks), so a +0.06 MRR difference is within noise and would need a bigger evaluation set to confirm.
